# V1.1 Feature Priority Research (2026-11-01)

针对"用户是否需要各文献类型的完整著录检查"的需求评估，结合需求证据、
技术可行性、标准依据与竞品现状，给出 V1.1 的功能优先级建议。
**本文是决策依据文档，不是已交付功能的说明。**

## 1. 需求证据

### 1.1 中文论文文献类型的实际分布

- 高校本科/硕士论文的引用构成中，**期刊论文 [J]、学位论文 [D]、图书 [M] 与
  电子资源 [EB/OL] 占绝对多数**；会议录 [C]、标准 [S]、专利 [P]、数据集
  [DS]、预印本 [PP] 为少数。依据：
  - 北航模板（2026-2027 学年）官方示例 15 条中：J×4、M×2（含析出）、
    EB/OL×2、P×2、R/OL、D/OL、N、S/OL、DS/OL、PP/OL、C×1 —— 官方示例刻意
    覆盖全类型，但正文示例引用集中在期刊与图书；
  - 人大模板示例：M、D、J（学生最常用三类）+ 空占位；
  - GB/T 7714—2025 附录 B 示例分布同样以 J/M/D/C/EB 为主。
- 真实论文中最常见的著录错误（各高校图书馆指南与编辑规范反复强调的）：
  缺引用日期、页码格式、卷期格式、析出文献格式、版次与出版地缺项。

### 1.2 用户工作流定位

- Reference Radar 的定位是**论文完成后的质量检查**（不是写作时的文献管理）。
  用户在此阶段已不再改动文献库，需要的是"对照标准找错并改对"。
- 用户明确 pain point（来自同类工具的公开讨论与高校指南的常见问答）：
  手工核对著录格式费时、Word 域引用切换手写后格式混乱、不同学校要求细节
  不一（页码范围符、"等/et al"、熙加空格等）。

## 2. 现有竞品方案（诚实对比）

| 方案 | 做什么 | 不做什么（= 本项目空间） |
|---|---|---|
| Zotero + CSL 样式 | 写作时按样式**生成**著录 | 不检查已写死的文本；换样式需重插 |
| NoteExpress / CNKI E-Study | 文献管理 + 部分查重 | 无独立的 GB/T 7714 著录核查报告 |
| 学校图书馆人工指南 | 人工对照规则 | 无自动化，覆盖率靠人 |
| 商业论文格式检查服务 | 收费、需上传论文到服务器 | 隐私顾虑；不针对 GB/T 7714 著录细节 |

结论：**"本地、免费、针对 GB/T 7714 的事后著录核查"是真实空位**，与
"引用编号一致性"（已实现）构成同一工作流的两个核心需求。

## 3. 技术可行性（基于现有解析器实测）

`extractFields` 已能从真实模板样本（北航 15 条、人大 3 条）解析出：
类型代码/载体代码（100% 命中）、年份、卷期（含"增刊1"）、页码（含压缩与
全角标点形态）、DOI、URL、引用日期。字段解析的置信度机制已就位，可以在
置信度不足时降级为"待复核"而不是误报——这正是新增著录格式检查的安全基础。

## 4. 标准依据（可核查的必备项）

- 2025 版第 8 章各类型"著录项目表"（如 8.14 表 14 数据集、8.5 期刊年卷期）
  给出**逐项必备性**——为"缺失必备项"检查提供确定性依据；
- 6.2 给出符号使用（页码短横线已实现为 RR-FMT-011；其他符号规则可同法扩展）；
- 7.1.2 给出"超过 3 个责任者加'，等'"——可检查但存在姓名切分的误报风险，
  适合"待复核"级别。

## 5. V1.1 优先级建议（按用户价值排序，不以实现难度排序）

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | **期刊 [J] 条目著录检查**：缺卷期、缺页码、缺出版年、`（1）`全角期号提示 | 覆盖面最大；必备项在 8.5 表中有明确依据；解析器已可靠取出这些字段 |
| P0 | **电子资源 [EB/OL] 检查补全**：缺 URL、引用日期格式非 YYYY-MM-DD | 真实样本中 4/7 条在线条目缺引用日期，RR-FMT-013 已验证价值 |
| P1 | **学位论文 [D] 检查**：缺学位授予单位/年份 | 高校用户第二大类型；格式相对固定 |
| P1 | **图书 [M] 检查**：缺出版地/出版社（区分"有则必备"与"必备"） | 常见缺项；注意 9.2 顺序编码制下无责任者可省略的特殊情形 |
| P2 | 责任者"等/et al"检查（>3 人加"等"） | 有条款依据（7.1.2）但姓名切分有误报风险 → 只做"待复核"级别 |
| P2 | 学校风格差异配置（如页码符号、标点全半角偏好） | 真实需求但各校不一，需要配置机制，避免内置断言过严 |
| 暂缓 | 著者-出版年制整体支持 | 改动范围大（解析+规则+文档）；等公开测试确认有足够需求再排期 |
| 不做 | 付费 AI 服务、云端上传检查 | 与本地优先定位冲突 |

## 6. 与公开测试的联动

上述优先级将在公开测试中验证：若用户报告的主要问题集中在某类型，
则提升其优先级；若期刊检查的误报率在真实样本上不可接受，则降级为
"待复核"输出形式。评估方法与指标沿用 `docs/external-validation.md` 与
`docs/real-docx-validation.md` 的精确集合方法。
