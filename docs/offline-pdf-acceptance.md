## 场景与结果（3 轮独立重复，每轮全新浏览器实例）

### 场景 A — 正常 PWA 安装 → 离线全流程（核心承诺路径）

| 轮 | SW 激活 | 页面受控 | 字体在 Cache Storage | 离线 DOCX+分析 | 离线 PDF | 页面错误 |
|---|---|---|---|---|---|---|
| 1 | ✓ | ✓ | ✓ runtime（在线首导后） | ✓ | ✓ 86883B | 无 |
| 2 | ✓ | ✓ | ✓ runtime | ✓ | ✓ 86886B | 无 |
| 3 | ✓ | ✓ | ✓ runtime | ✓ | ✓ 86897B | 无 |

三轮离线 PDF 经 pypdf 复核：**1 页、85KB、含中文标题"检查报告"、引用统计、
文献表 [1]–[5]、条款号 9.2、顺序编码制覆盖声明**——文本可选取、无乱码。

### 场景 B — Cache API 字体回退（v1.1.2 修复的验证）

- **B1（回退数据源）**：一次在线导出后，生产站点上 `caches.match(字体URL)`
  三轮全部命中：`NotoSansSC-Subset.otf, status=200, bytes=11179892`。这正是
  fetchFont 在网络获取失败时所调用的接口——**回退数据源在生产站点验证通过**。
- **B1-end-to-end（受控页面）**：场景 A 的离线导出本身就是"网络获取失败 →
  运行时缓存命中"的完整链路，三轮全过。
- **B2（已知限制，如实记录）**：注销 SW 后**刷新**页面再离线导出——无控制
  页面没有可离线加载的应用壳，导航失败；此时整个应用（含 PDF 模块）都不可
  用，不仅是字体。这是"未安装 PWA 就无法离线使用"的既定边界，错误信息为可
  操作指引而非挂起。另发现：正常路径下 SW 服务的响应不进入 HTTP 磁盘缓存，
  因此"刷新后靠 HTTP 缓存恢复"不可依赖——这正是必须安装 PWA 的原因，已写入
  用户教程。

### 场景 C — 首次访问即离线（无安装、无缓存）

三轮全部：导航失败（无 SW、无缓存，应用不可能凭空出现），**无挂起**；恢复
网络后新访问立即正常。与文档声明一致：不宣称未安装即可首次离线使用。

### 场景 D — 网络恢复

三轮全部：恢复网络后应用立即恢复正常。

## 过程中发现并处置的问题

1. **在线导出偶发超时**（90s 窗口，含 10.6MB 字体首次加载）：网络抖动所致。
   处置：测试超时放宽至 180s/120s 并增加渐进日志；产品无缺陷（重试即过）。
2. **第三轮出现一次"字体不在缓存"的离线导出失败**：当时在线导出因网络失败
   未完成，字体未入缓存——**v1.1.2 新增的回退错误信息按设计触发**（清晰中文
   指引"请联网导出一次以缓存字体，或改用 HTML 报告"，无挂起，请求失败被完整
   记录）。该行为验证了错误路径的正确性。
3. **Chromium "Target crashed"**（第 3 轮末）：9+ 个浏览器上下文各自持有
   10.6MB 字体 ArrayBuffer 导致的测试机资源压力，测试环境问题；已加固脚本
   失败分支，产品无涉及。

## 结论

- **场景 A（产品承诺路径）三轮全过**：安装→离线导入→分析→PDF 导出，PDF
  内容经 pypdf 独立复核。
- **场景 B1 回退数据源在生产站点验证通过**；完整的"无控制页面离线导出"
  依赖已加载的模块，其边界（刷新即失效）已如实记录并给出可操作指引。
- **场景 C/D 符合文档声明**。
- **无需发布 v1.1.3**：未发现正常路径（已安装 PWA）下的未修复缺陷。
